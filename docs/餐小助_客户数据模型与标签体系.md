# 餐小助·商户智能经营助手：客户数据模型与标签体系

---

## 1. 设计目标

本数据模型面向中小餐饮商户日常经营场景，支撑客户识别、客户分层、菜品分析、采购预测、营销触达等AI应用。设计原则：

- **OneID优先**：同一客户在不同平台下单，必须能合并为统一档案。
- **可计算**：所有标签和指标必须有明确的计算规则，可定时跑批更新。
- **可扩展**：预留JSON字段，支持商户自定义菜品属性、过敏原、推荐规则。
- **合规安全**：手机号、身份证等敏感字段哈希/加密存储，展示时脱敏。

### 2.2 OneID匹配规则

1. **强匹配**：手机号一致，直接合并。
2. **中匹配**：手机号为空但微信UnionID一致，合并。
3. **弱匹配**：同一门店同一平台同一姓名+相似地址，人工复核后合并。
4. **冲突处理**：同一人多个手机号，以最近活跃手机号为主，其余挂附属。

### 3.2 利润计算口径

```
真实利润 = 实付金额 - 平台扣点 - 包装费 - 食材成本 - 退款金额 - 优惠分摊
```

说明：
- 平台扣点按各平台实际费率计算。
- 包装费若由商户承担则计入成本，若向客户收取则计入收入。
- 优惠分摊按菜品原价比例分摊到每道菜。

### 4.2 菜品四象限分类规则

```
销量分位 = 菜品销量在统计周期内的百分位
毛利分位 = 菜品毛利在统计周期内的百分位

明星菜：销量分位>0.7 且 毛利分位>0.7
引流菜：销量分位>0.7 且 毛利分位<=0.7
利润菜：销量分位<=0.7 且 毛利分位>0.7
淘汰菜：销量分位<=0.3 且 毛利分位<=0.3
```

## 6. 核心指标体系

### 6.1 经营指标（8个）

| 指标名 | 公式 | 正常区间 | 异常阈值 | 用途 |
|--------|------|----------|----------|------|
| 毛利率 | （营收-食材成本）/ 营收 × 100% | 50%-70% | <40% | 整体盈利能力 |
| 真实利润率 | （实付-平台扣点-包装-食材-退款）/ 实付 × 100% | 20%-40% | <10% | 老板到手利润 |
| 客单价 | 实付金额 / 有效订单数 | 25-60元 | 较上周波动>20% | 消费力评估 |
| 订单量 | 统计周期有效订单总数 | 依门店规模 | 较上周波动>30% | 生意热度 |
| 退单率 | 退款订单数 / 总订单数 × 100% | <3% | >5% | 品控/服务监控 |
| 差评率 | 差评数 / 评价总数 × 100% | <5% | >10% | 口碑监控 |
| 营收增长率 | （本期营收-上期营收）/ 上期营收 × 100% | 5%-20% | <-10% | 增长健康度 |
| 利润增长率 | （本期利润-上期利润）/ 上期利润 × 100% | 5%-20% | <-15% | 利润健康度 |

## 9. 数据质量校验规则

| 校验项 | 规则 | 处理方式 |
|--------|------|----------|
| 手机号格式 | 11位数字，符合国内号段 | 非法手机号标记为匿名客户 |
| 订单金额异常 | 实付金额>0且<5000元 | 超出范围进入异常订单池 |
| 时间异常 | 下单时间不得晚于当前时间 | 标记为脏数据，人工复核 |
| 菜品成本缺失 | 成本价为空时无法计算毛利 | 提醒商户补录，缺失期间用历史均价 |
| OneID冲突 | 同一手机号匹配多个客户 | 进入合并任务队列 |
| 重复订单 | 同一平台同一订单号重复 | 去重，保留最新一条 |
