# 本地向量检索（复用 Ollama）

项目使用电脑上已有的 Ollama `bge-m3:latest`，不再安装独立 Python、PyTorch 或下载另一份 Hugging Face 权重。向量在本机生成，无需向量 API Key；对话模型仍使用后端单独配置的服务。

`backend/.env` 当前配置：

```dotenv
EMBEDDING_PROVIDER=local
EMBEDDING_API_KEY=
EMBEDDING_BASE_URL=http://127.0.0.1:11434/v1
EMBEDDING_MODEL=bge-m3:latest
EMBEDDING_DIMENSIONS=1024
EMBEDDING_MIN_SIMILARITY=0.35
```

双击原有 PC/手机端启动脚本即可。脚本先复用 Ollama；服务未运行时，在后台启动已安装的 Ollama 应用，沿用应用设置的模型目录。不会自动下载模型。`start-local-embedding.ps1` 和旧的 `setup-local-embedding.ps1` 也只检查、启动现有服务。

当前电脑的 Ollama 位于 `D:\Ollama`，模型目录为 `D:\Ollama\model`。保留 `bge-m3:latest` 和其他已有模型。一键停止只停止本项目的前后端，不终止共享的 Ollama。

## 使用资料

在「AI 经营助手 → 门店资料」导入采购规范、供应商报价与配送约定、验收记录等，再点击「更新语义索引」。首次启用或更换模型、接口地址后需重新建立索引。每批最多处理 10 个片段，已完成部分可续建。门店、资料版本和生效日期的过滤规则保持一致。

索引存放在现有 SQLite 的 `AgentKnowledgeEmbedding` 表。Ollama 负责生成 1024 维向量；项目完成关键词与向量排序融合、返回原文引用。库存、价格和采购数量仍由业务工具查询、计算。

## 排查与验证

本地请求超时为 30 秒，允许模型首次加载；远程接口仍为 12 秒。服务不可用或索引未完成时会回退到关键词检索，并显示原因。显存不足时，先检查是否有其他大模型同时占用显存。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start-local-embedding.ps1
cd backend
npm run verify:knowledge:real
```

真实评估使用隔离模拟数据库，不调用对话模型。在同一批 18 个采购问题上，Ollama 与原 Python 版均为目标资料前 4 个片段命中 17/18；这不是大模型回答正确率。详见 [真实混合检索评估](../模拟验证/采购核对/验证报告/真实混合检索评估.md)。
