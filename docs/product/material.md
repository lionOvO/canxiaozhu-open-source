# Material: 餐小助项目答辩

## 1. Overview
- 餐小助是面向中小餐饮商户的AI智能经营助手，定位为"数字店长"
- 核心目标：让AI帮老板盯店，老板只管做好菜
- 核心价值：单店月均降本3000元以上，增收5000元以上，综合经营效率提升30%
- 产品形态：PC商户后台 + 手机商户端 + 顾客扫码点餐页

## 2. Background
- 中国餐饮AI市场规模突破800亿元，但80%产品集中在C端场景
- 中小餐饮平均寿命仅18个月，主要死因不是口味，而是"不会算账、不会管客、不会控损耗"
- 现有竞品（美团收银、客如云、二维火）侧重收银和门店管理，AI经营决策能力弱
- 餐小助避开收银红海，专注"经营分析+智能决策"

## 3. Key Info
- 技术栈：Vue3 + Pinia + Vue Router + ECharts（前端）/ Fastify 5 + Prisma 6 + TypeBox + OpenAI SDK（后端）
- 部署：Docker Compose + Nginx + 腾讯云
- AI模型路由：DeepSeek-V3（主力推理）、通义千问-Max（复杂BI）、豆包-Pro（创意文案）、文心一言-4.0（NLP分类）
- 数据模型：OneID跨平台客户统一标识、RFM分层、38个客户标签、菜品四象限
- 8大模块：AI经营驾驶舱、客户资产管家、菜品盈利分析、智能采购与库存、智能定价与促销、员工与排班、评价与口碑、系统管理

## 4. Evidence
- Case: 社区快餐店老王 - 每日对账时间从2小时降至10分钟，损耗率从12%降至5%
- Case: 早餐店老板娘阿芬 - 语音问"这周怎么样"直接出答案，每天节省决策时间1.5小时
- 竞品对比：餐小助在经营分析、客户运营、库存预测、定价促销四个维度均强于传统竞品
- 技术亮点：SSE流式AI回复、OneID智能合并、真实利润计算引擎、销量预测+智能采购单

## 5. Analysis
- 问题1：AI非流式返回导致用户误以为卡死 → 采用SSE流式输出+打字机效果
- 问题2：未连接模型时不能返回虚假分析 → 数据真实性校验+置信度标注
- 问题3：天气IP定位不准确 → 多源定位+手动修正
- 问题4：服务器显示旧页面 → Nginx缓存清理+版本化部署
- 问题5：二维码使用localhost导致外网打不开 → 公网域名配置
- 问题6：Docker部署端口和路径冲突 → 标准化Docker Compose配置
- 问题7：取消订单被错误计入销量 → 订单状态机白名单校验

## 6. Outlook
- 从"会写页面"走到"能交付系统"
- 掌握了Vue3多端开发、Fastify接口设计、Prisma数据建模、AI流式问答、Docker部署
- 理解了经营类系统必须保证数据真实，不能为了页面好看而误导用户
- 未来可扩展连锁版、供应链比价、AI外呼召回
