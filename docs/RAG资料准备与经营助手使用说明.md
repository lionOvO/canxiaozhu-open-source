# 门店采购资料与经营助手

## 先准备什么资料

第一版围绕采购前的补货核对，优先准备以下三类资料，每份资料都需要真实来源和负责人核实。

| 分类 | 建议内容 | 用途 |
| --- | --- | --- |
| 采购规范 | 采购前的核对步骤、盘点要求、异常上报方式、采购建议的审核流程 | 解释本店应该怎样核对采购建议 |
| 供应商说明 | 真实订货说明、订货截止时间、起订要求、包装规格、配送约定 | 查找已确认的订货条件；预设供应商档案不代表真实承诺 |
| 异常处理 | 已确认的到货不足、重复采购、数量不符等处理记录或标准流程 | 提供可追溯的处理依据 |

不要把实时库存、销量或订单流水反复复制进资料：助手会调用业务服务查询这些数据。采购计算公式、金额和单位换算继续由业务程序执行。密钥、客户隐私、未经核实的聊天记录以及项目 PRD，不应作为门店采购规定导入。

没有真实资料时，知识库保持为空。系统会说明没有找到有效依据，不会自动生成供应商条款或门店制度。

## 如何整理

每份资料填写名称、分类、版本、来源、生效日期；可选填写失效日期。当前资料只适用于导入时选中的门店。

正文建议使用 Markdown 章节组织；也支持 UTF-8 TXT。首次可整理少量经过确认的文件。支持粘贴正文或选择文件，不支持直接解析 PDF、图片和扫描件；请先核对并另存为文本。

以下只是整理结构，方括号必须换成真实内容，不是可直接使用的采购制度：

```markdown
# 适用范围
[说明哪些门店、食材或采购场景适用]

# 采购前核对
[填写已确认的核对步骤]

# 订货要求
[填写有真实依据的条件，注明供应商与出处]

# 异常处理
[填写已确认的处理流程及责任人]
```

单份正文限制为 20～60000 字，文件不超过 200 KB。每家门店最多启用 50 份资料。同名资料不允许生效时间重叠，更新前先停用旧版或设置不重叠的生效期间。

## 批量导入与重新启用

在“门店资料 → 导入新资料”一次选择多个 Markdown / TXT 文件，每批最多 20 个。每个文件独立保存为一份资料，文件名默认用作标题和来源，可逐份修改分类、名称，展开“版本、日期与正文”核对其他信息。也可继续添加文件，或移除不需要导入的待处理项。

点击“导入并启用”后逐份处理，列表显示成功状态与具体失败原因。修正失败项后重试时，成功文件不会再次提交。超出格式、编码、容量或日期限制的文件不会被默默跳过；单份失败也不阻止其余文件导入。切换门店后停止提交后续文件。

已停用资料右侧显示“启用”。重新启用会保留原资料 ID、版本和正文，并重新校验管理权限、门店范围、50 份启用上限及同名版本的生效期冲突。已过期或尚未生效的资料，即使启用也只在其生效期内参与检索。

新导入资料后请查看检索状态，按需点击“更新语义索引”。重新启用的资料若已有相同模型、正文的有效向量，则直接复用；否则显示待建立索引。

## 如何使用

1. 登录 PC 后台，打开左侧“AI 经营助手”，或点击其他页面右下角“问问小助”。
2. 选择正确门店。具有系统管理权限的账号可通过“门店资料”单份或批量导入、停用和重新启用资料；其他已授权门店账号可以查阅。
3. 点击“明天该补哪些食材”，或输入“核对明天采购建议，查阅本店采购规范，说明依据和待确认事项”。
4. 中间查看回答和采购试算表，右侧查看实际查询步骤；展开资料卡查看检索原文、版本及来源，可继续打开完整资料。
5. 前往库存页面核对未盘点项，再到采购单页面复核。助手不会直接确认采购、修改库存或替用户下单。

支持 Enter 发送、Shift+Enter 换行、停止生成、新对话、复制回答。当前对话保存在页面运行期间，多轮请求携带最近八条历史消息；切换门店会重置对话。服务端保存问答日志，不提供跨请求 LangGraph 图状态恢复。

## DeepSeek 配置

在 `backend/.env` 填写：

```env
AI_PROVIDER=deepseek
DEEPSEEK_API_KEY=填写真实密钥
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

之后重启后端。Docker 部署在服务器 `.env.docker` 填写相同变量。密钥不应贴到聊天、前端、文档或资料库。

当前实现使用 DeepSeek 官方 OpenAI 兼容 Chat Completions 接口，关闭思考模式，运行模型—工具—模型循环。每次最多八次工具调用，图递归上限十二步，总超时九十秒。配置状态仅表示密钥已填写，不代表远程服务已经连通。

参考：[DeepSeek 接口说明](https://api-docs.deepseek.com/)、[工具调用说明](https://api-docs.deepseek.com/guides/tool_calls/)。

## 当前检索实现

资料正文、章节片段、版本和日期持久化在现有 SQLite 的独立 `AgentKnowledgeDocument` 表中。首次访问时增量创建表，不重置业务数据；Docker 复用数据库持久化卷。查询先按服务端授权门店、生效区间和启用状态过滤，再对中文词片段与英文词做关键词加权排序，每次返回最多四个原文片段。

这是第一版关键词检索 RAG，不使用向量数据库，也没有训练或微调模型。库存、销量来自业务接口；起订量等文档要求暂列待核实事项，不自动改变采购算法。后续可用真实问题集衡量漏检，再决定是否增加向量检索。

## 验证

在 `backend` 执行 `npm run check`、`npm run build`、`npm run verify:agent` 和 `npm run verify:knowledge`。知识库验证使用独立临时数据库和本地模拟模型，不向真实门店导入测试资料。真实模型联调需先配置密钥，再运行 `npx tsx scripts/smoke-business-agent.ts`。

在 `front-pc` 执行 `npm run type-check` 与 `npm run build`。
