# 采购资料混合检索

当前实现将关键词检索与语义检索融合，检索对象仍是各门店导入的采购规范、供应商说明和异常处理记录。销量、库存、在途数量、采购试算继续由业务工具实时查询，向量检索不负责计算数量，也不修改采购单。

## 配置与启用

本地 BGE-M3 无需向量 API Key。当前复用电脑已有 Ollama，按 [本地部署说明](../../docs/本地向量检索.md) 启动并更新索引；以下 Key 配置步骤仅适用于远程百炼服务，切换远程时需设置 `EMBEDDING_PROVIDER=remote`。

1. 在 `backend/.env` 填写 `EMBEDDING_API_KEY`，密钥仅保存在后端，不要填写到前端环境变量或聊天消息中。
2. 默认模型为百炼 `text-embedding-v4`，维度为 1024。默认地址对应北京地区；Key、模型权限和地区必须匹配。若使用其他地区或工作空间专用域名，同时修改 `EMBEDDING_BASE_URL`。
3. 重启后端；若正在运行独立模拟服务，也需重启模拟服务，使进程重新加载环境变量。
4. 在“AI 经营助手 → 门店资料”查看检索状态，使用具有系统管理权限的账号点击“更新语义索引”。这会把当前门店有效资料的标题、章节和正文片段发送至配置的向量服务。每次最多 10 个片段，界面显示完成进度，可暂停并继续。
5. 完成后状态显示“关键词 + 语义检索”。新导入资料、生效日期变化、模型/维度/服务地址变化时，需要再次更新索引。修改 Key 不要求重算已有向量。

```dotenv
EMBEDDING_API_KEY=在本地填写百炼对应地区的Key
EMBEDDING_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
EMBEDDING_MODEL=text-embedding-v4
EMBEDDING_DIMENSIONS=1024
EMBEDDING_MIN_SIMILARITY=0.35
```

向量 Key 独立于 `QWEN_API_KEY` 等对话模型配置，不会自动复用。可填写同一百炼账户具有相应权限的 Key，但账户额度和模型授权仍需可用。向量接口可用并不代表对话模型一定可用。

百炼文档：[Embedding 兼容接口](https://help.aliyun.com/en/model-studio/embedding-interfaces-compatible-with-openai)。默认 `text-embedding-v4` 支持 1024 维、每批 10 条。现有 dashscope 域名仍可用，也可配置控制台工作空间的专用域名。

## 检索过程

1. 先按授权门店、启用状态和上海时区业务日期筛选资料；过期、待生效、停用及其他门店资料都不进入本次索引或候选集合。
2. 原文按章节分段，保留资料、版本、章节、来源和生效日期。
3. 关键词侧沿用中文双字词与字母数字词项的频率排序；语义侧调用向量接口转换问题，用归一化向量计算余弦相似度。
4. 低于 `EMBEDDING_MIN_SIMILARITY` 的语义候选被排除，两个排序通过 RRF 融合，返回前 4 个原文片段。该阈值是初始值，需结合真实评估调整，不代表概率或正确率。
5. Agent 只能引用实际返回的原文，前端保留 `[S1]` 等引用和“查看完整资料”。“送少了怎么办”可能对应多种食材，仍需澄清供货人及订单，不能把复盘材料当成当前交易事实。

## 存储与故障处理

向量缓存在现有 SQLite 的 `AgentKnowledgeEmbedding` 表中，不额外部署向量数据库，适合当前每店最多 50 份资料的规模。表按需创建，不重置业务数据库。资料 ID、片段序号、文本哈希、模型/服务地址/维度的指纹用于判断缓存能否复用；不同模型的向量不会混算。

远程模式没有 Key、索引未完成或接口故障时，使用关键词检索并在状态和工具结果中说明原因。本地向量接口请求超时为 30 秒，远程为 12 秒；查询失败后短暂退避 30 秒，避免每次提问反复请求故障服务。索引失败保留已完成批次，修复配置后可再次点击更新。服务响应正文和 Key 不回传前端。

索引接口为 `POST /api/v2/agent/knowledge/index`，请求体 `{ "shop_id": 910101 }`，要求登录、具有当前门店权限及 `settings` 权限。状态接口沿用 `GET /api/v2/agent/status?shop_id=910101`，新增独立的 `embedding` 状态。建立索引是显式操作，问答请求不会自动将全部资料向量化。

## 验证

在 `backend` 运行：

```powershell
# 不需要 Key，使用临时数据库及预设向量接口测试程序行为
npm run verify:knowledge:hybrid

# 本地 Ollama 可直接运行；远程服务需先填 Key。仅使用隔离模拟材料，不调用对话模型
npm run verify:knowledge:real
```

第一条覆盖权限、日期、版本、分批续建、坏向量拒收、模型切换、哈希失效、资料停用、RRF、原文引用、接口错误回退与响应脱敏。预设向量不代表真实语义质量。

第二条每次创建独立模拟数据库，先在同一批资料上获取关键词基线，再建立真实向量索引，比较 10 个直接问题、5 个改写问题和用户标注的 3 个问题。结果保存为 `验证报告/真实混合检索评估.json` 与 `.md`；有接口错误时明确记录未完成，不能把关键词回退当成向量测试通过。指标是目标材料能否进入前 4 个片段，不是大模型回答正确率。

当前已使用本地 Ollama BGE-M3 完成真实向量评估：关键词命中 11/18，混合检索命中 17/18，用户标注的 3 个改写问题全部命中。详细结果在 `验证报告/真实混合检索评估.json`。原有 `关键词检索评估.json` 保留为关键词基线。
