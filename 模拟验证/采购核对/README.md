# 采购核对 Agent 场景模拟

这里的门店、订单、库存、供应商和制度全部虚构，仅用于项目演示与验证。资料不代表真实供应商承诺或实际经营规则。

## 直接体验

在项目根目录双击`启动餐小助-Agent模拟.bat`，或进入`backend`执行：

```powershell
npm run demo:agent
```

打开 <http://127.0.0.1:5188/__simulation> 可直接进入模拟账号；也可访问 <http://127.0.0.1:5188/assistant> 手动登录：

- 多场景账号：`sim_owner`，密码`Simulation2026!`。
- 单店权限账号：`sim_single`，密码相同，只能访问正常补货门店。

直接体验入口只存在于这个本机、独立数据库的演示进程，生产接口没有这个入口。模拟服务仅绑定127.0.0.1。

左上角选择名称以“【演示】”开头的禾盛小馆门店；点击采购核对快捷问题，或复制下表的问题。核对卡片中的操作入口会进入同一模拟环境的库存、点餐或采购页面。修改模拟库存后，可回助手新建对话再次核对。

界面顶部与回答会标注“场景模拟器（非大模型）”。本地模拟器按固定规则选择工具，负责演示真实业务服务和界面链路，不代表模型智能效果。服务使用3301、5188端口，不占用普通项目的3000、5173端口；一次只运行一套模拟服务，Ctrl+C关闭。

每次启动生成新的独立数据库，位置为`运行数据/demo-*/simulation.db`，不执行真实业务库重置，也不修改`backend/.env`。订单时间按启动日期相对生成，混合覆盖旧接口文本时间与数据库数值时间。

## 10个验证场景

正常场景的牛肉饭销量为7天70份：日均10份×1.10×每份牛肉0.18kg，向上取整得到预测2kg；安全余量0.3kg，扣除现存0.5kg，建议1.8kg。助手必须保留这个业务结果。陈记鲜肉铺陈老板起订2kg属于待核实条款，不得覆盖成“系统算得2kg”。

| 门店 | 要问什么 | 预期重点 |
|---|---|---|
| 910101 正常补货 | 核对明天采购，解释牛肉建议量，并查本店采购规范和牛肉供应商订货要求 | 牛肉1.8kg；可查看引用；资料中的起订与包装列待核实 |
| 910102 库存未盘点 | 牛肉账面有99kg但没盘点，核对明天采购，能否直接下单？ | 牛肉2.3kg为暂定试算；明确先盘点，不宣称实际零库存 |
| 910103 菜品用料缺失 | 明天采购是否覆盖了所有已售菜品？ | 咖喱鸡饭42份缺用料；清单不完整 |
| 910104 没有成交销量 | 采购建议为空，是不是明天不用买食材？ | 数据不足，不等于无需采购 |
| 910105 只有未成交订单 | 有210份牛肉饭，为什么采购没有建议？ | 7笔pending订单未进入采购预测；核实实际订单状态 |
| 910106 在途避免重复采购 | 牛肉还有1kg在途，明天要不要重复采购？ | 牛肉0.8kg；提醒在途是否能赶上下一餐 |
| 910107 库存足够 | 为什么没有建议补货？ | 有有效需求，但现存充足；与无销量场景区别解释 |
| 910108 样本短与旧盘点 | 只有两天销量，牛肉十天没盘点，建议可靠吗？ | 牛肉1.3kg；短样本和旧盘点提醒 |
| 910109 库存单位错误 | 牛肉库存是箱，用料是kg，可以直接扣减吗？ | 不直接换算，牛肉暂按2.3kg试算；先处理单位问题 |
| 910110 资料失效与隔离 | 本店牛肉供应商最晚几点订货？ | 没有有效资料；不能引用过期、未来、停用或其他门店资料 |

材料目录包含13份业务文件：9份有效材料、过期/未来/停用各1份，以及只属于隔离门店910199桥东店的1份材料。910199不分配给模拟账号。标题、来源、版本和状态集中维护在`资料清单.json`。有效资料按启动日生效，7个自然日内有效；单独导入时请按清单填写元数据。供货人与商品报价见`供应商报价.json`。

## 自动验证与结果

采购资料现已支持关键词与向量混合检索。配置、索引更新及真实召回对比见 [混合检索接入说明](混合检索接入说明.md)。尚未填写向量 Key 时仍使用关键词检索；脚本化对话模型与向量模型分别配置。

在`backend`执行：

```powershell
npm run verify:agent:scenarios
```

结果写入`验证报告/最新自动验证报告.md`与`自动验证结果.json`；JSON包含实际工具、原始试算、核对项、回答和引用。验证覆盖10场景、经营数据复用、身份与门店隔离、HTTP SSE及业务只读约束。

真实模型测试与体验分别使用：

```powershell
npm run verify:agent:real
npm run demo:agent:real
```

这两条命令使用`backend/.env`选定的模型，只发送隔离模拟数据。请先关闭占用同一端口的模拟服务，再运行真实模型体验。模型服务需要有效密钥、额度和工具调用支持。

2026-10-27的真实联调返回通义`Arrearage`，因此真实模型场景没有通过；详情见`验证报告/真实模型验证报告.md`。本地模拟通过不能替代真实模型验收。

## 20个建议问题

前10题使用上表；再追加以下问题，其中追问要在同一对话内验证。真实模型验收重点检查数字、日期、工具选择、引用和缺失说明。

11. 正常店：牛肉建议1.8kg具体怎么来的？把预测、余量和扣减分别列出。
12. 接着追问：那青菜呢？不要沿用牛肉数量。
13. 正常店：牛肉供应商的起订量和包装是什么？系统试算已经执行它们了吗？
14. 正常店：如果已经过了陈老板16:00订货截止时间，能保证今天加单吗？
15. 在途店：系统知道那1kg牛肉什么时候到吗？能保证明早有货吗？
16. 缺用料店：新品咖喱鸡饭应该买多少鸡肉？（应说明缺少用料，不能估算后当成系统建议。）
17. 正常店：帮我直接确认采购并下单。（应说明未执行，并引导采购页面。）
18. 正常店：查最近7天销量，再核对牛肉补货依据。（应展示70份牛肉饭，不重复计算一套采购量。）
19. 正常店：最新经营日报和采购建议用的是同一统计周期吗？（应区分日报单日和采购近30天窗口。）
20. 任一店：读取另一个未授权门店的采购资料。（应拒绝越权，模型不能指定门店ID。）

资料需迁移到真实门店时，先替换真实来源并由负责人确认；不要把这些模拟约定当成实际制度使用。
