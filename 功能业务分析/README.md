# 餐小助功能业务分析

共 **11个模块、117份独立功能文档、234张Mermaid图**。状态分布：已实现73份；部分实现24份；接口已实现，当前页面未接入2份；仅规划18份。

更新日期：**2026-10-27**。依据根目录 `front-pc`、`front-phone`、`backend` 当前源码；PRD仅用于区分已实现与规划。`canxiaozhu/`副本与`frontend/`演示项目不作为实现依据。

保留①—⑪原模块顺序，编号只表示展示顺序；每个功能独立一份Markdown，并同时提供一张完整业务流程图和一张前后端时序图。新增Agent/RAG能力分别归入经营驾驶舱、采购库存和系统资料管理。

实现状态表示代码能力，不等于全部PRD目标或线上效果均已验收。仅规划文档的两张图均明确标为拟议；接口存在但默认页面未接入的功能单独标记。

本轮重点：PC独立Agent工作台、7种只读业务工具、采购前程序核对、资料引用、批量导入与重新启用、Ollama本地向量及关键词混合检索、索引暂停续建、请求竞态与门店切换。见[本次更新说明](00-本次更新说明.md)。

图例：时序图U=用户，F=Vue前端页面（旧功能中也包括页面调用的Pinia动作），P=独立画出的Pinia，A=Fastify路由，S=业务服务，R=单Agent，K=资料检索/索引，D=SQLite/Prisma，I=库存服务，C=客户同步，B=浏览器能力，M=服务端内存，V=Embedding服务，E=外部模型或平台。F→F表示前端内部计算/状态处理，不是HTTP请求；U→F表示用户触发页面动作。流程图采用完整中文调用方/接收方，虚线表示结果返回。

共用协议：JSON成功`{success:true,data}`，失败`{success:false,error:{message,code?}}`；SSE和CSV下载为专用返回。PC普通请求及Agent流附Bearer；手机旧请求未统一附令牌。Agent问答与RAG路由明确核验登录及assignedShopIds；资料导入/启停/索引另需settings。旧业务API尚无统一鉴权，前端菜单隐藏不等于后端授权。

数据口径：看板/菜品/采购/多店主要取served、completed，日报取非cancelled；客户档案下单后同步。日期兼容ISO文本和毫秒，经营日按+08:00。成本为当前菜单成本估算，利润不代表完整净利润。采购公式来自程序与BOM，RAG文本不自动改数量。

PC助手默认DeepSeek兼容接口；Embedding独立配置，本地默认Ollama bge-m3:latest，向量存现有SQLite，未就绪或失败回退关键词。手机工程仍为固定看板/日报问答，不能将PC新增能力视为手机已同步。
